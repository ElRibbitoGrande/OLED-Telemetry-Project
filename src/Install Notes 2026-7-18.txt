OLED Telemetry Project – Current Architecture
Current Status
Stable Windows/Rainmeter implementation.
Denon AVR-X3700H telemetry working.
Quick Select number and friendly names working.
OLED Quick Select display implemented.
Telemetry manager architecture proven.
Design Principles
Be gentle with the Denon X3700H.
Treat it as an embedded device with a limited networking stack.
Prefer Telnet for live telemetry.
Use HTTPS only for slow-changing configuration.
Cache aggressively.
Serialize HTTP requests.
Never let optional metadata delay live telemetry.
Separate collectors.
AVR collector
WiiM collector
Apple Music collector
Future collectors should never block one another.
Single state model.
Collect data independently.
Merge into one in-memory state.
Update the display from one consolidated state.
Only poll at the rate information can change.
Volume/mode/source: fast.
Configuration: slow.
Static metadata: startup or infrequently.
Design around events instead of polling whenever possible.
Pi v2 Philosophy

Do not port the PowerShell implementation.

Instead:

rewrite from scratch
preserve architecture
preserve UI
preserve protocol knowledge
eliminate Windows-specific workarounds
Known Denon observations
Telnet is extremely reliable.
HTTPS configuration endpoints are useful but fragile.
Concurrent HTTPS requests can destabilize the AVR's network services.
The iPhone app and OLED can both become stale while the AVR itself continues operating normally.
Rebooting the AVR restores the network control subsystem.
Long-term Goals
Pi-hosted telemetry manager
Native OLED driver
WiiM metadata integration for the Schiit Lyr+ input
Album art
VU meters
Minimal disk writes
Modular services
Automatic recovery
